# One-page proposal

*The page that asks for the **next stage** of an AI use case — not the whole programme. It is an
argument, not a description: the problem in the reader's terms, why this beats the alternatives, the
risks admitted, and a specific ask. Write it for the person who decides at the gate. If it does not
fit on one page, the ask is too big.*

*Each prompt has an example in italics, from a worked example (a fictional insurer fast-tracking small
claims; synthetic numbers). Delete the examples when you fill it in.*

| | |
|---|---|
| **To** (decides at the gate) | |
| **From** (owns the use case) | |
| **Date · version of this page** | |
| **Stage asked for** | ☐ 1 Worth doing? ☐ 2 Can a model learn it? ☐ 3 Does it help people? ☐ 4 Can we keep it working? |

## 1. The problem, in the reader's terms

Two or three sentences, in money, time or customers — today's numbers, errors included.

*Example: Handling small claims costs about €2.5 million a year, takes a median of eight working days,
and still pays about €950,000 a year in fraud.*

## 2. The decision this improves

The decision · the information missing when it is made · the action that follows · who owns the
result.

*Example: Pay, deny or investigate a small claim · is it covered, is it genuine · a payment, a letter or
a referral · the head of claims.*

## 3. What we ask for

Only the next stage: how long, which people, what budget — and what is **not** asked for yet.

*Example: Eight weeks; senior handlers and the fraud desk to re-check 3,000 claims; the evaluation
team. Not asked for now: integration, the knowledge base, go-live.*

## 4. The gate for this stage — written now

| | Criteria | |
|---|---|---|
| **Go** if | | *rule and model lower the euro cost of errors against today's process, at ≥ 35% automatic* |
| **Change course** if | | *cheaper in errors, but below 35% automatic* |
| **Stop** if | | *not cheaper than today's process* |
| **Decided by · on** | | *name · date* |

## 5. Why this beats the alternatives

One line each. Always include doing nothing and the simplest rule.

| Alternative | Why not, or why later |
|---|---|
| Do nothing | *The cost in §1 stays; customers keep waiting eight days.* |
| The simplest rule | *Takes the first 30%; it goes live first, but leaves 70% on the desk.* |
| Buy, or switch on what we already pay for | *Tested on the same checked claims in this stage.* |
| Build the whole thing now | *Commits the full budget before we know a model can learn it.* |

## 6. If it works

Today · proposed · the errors the new way makes, counted · net a year · payback. Then the low case: the
same at the pessimistic assumption.

*Example: ≈ €2.5M → ≈ €0.8M; the fast track's own errors ≈ €64,000 more; ≈ €1.28M net; payback
≈ 8.5 months. Low case (35% automatic): ≈ €1.13M net; ≈ 9.5 months.*

## 7. The number that breaks it

The one figure that, if it moves, turns the case. How this stage measures it.

*Example: Fraud paid (≈ €952,000 today). Up a quarter, net falls to ≈ €1.04M. This stage estimates it on
the checked claims; shadow mode measures it before anything is automatic.*
